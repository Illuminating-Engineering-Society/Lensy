Paste IES Lens into the Vitrium portal

Two snippets for Portal Settings → Portal Header in Vitrium Security (the portal at lighting.ies.org/portal/ies). Use either or both.

1 · Welcome panel

"A way to guide users to IES Lens and tutorials when they first land in Vitrium." A floating card in the bottom-right corner, dismissible, that does not cover the portal's own controls.

Preview

Looking for something specific? Ask a question in plain language and IES Lens finds the passages, tables and citations across the whole Lighting Library.

Search with IES Lens Tutorials

HTML to paste

<!-- IES Lens welcome panel. Dismissible with no JavaScript; the optional
     script at the end only makes the dismissal stick between visits. -->
<style>
#ieslens-welcome-dismiss { position:absolute; opacity:0; pointer-events:none; }

  border-radius:16px; box-shadow:0 12px 32px rgba(44,44,44,.18); padding:18px;
  font-family:-apple-system,BlinkMacSystemFont,'Segoe UI',Inter,sans-serif;
  color:#2C2C2C; text-align:left; line-height:1.5; }

  font-size:20px; line-height:1; color:#9ca3af; padding:2px 6px; border-radius:6px; }
#ieslens-welcome img { height:42px; width:auto; display:block; margin-bottom:10px; }
#ieslens-welcome p { margin:0 0 14px; font-size:13.5px; }

<!-- OPTIONAL. Without it the panel returns on every visit; with it, a reader
     who closes it stays closed. If Vitrium strips scripts, delete this block —
     everything above still works. -->
<script>(function(){try{
  var b=document.getElementById('ieslens-welcome-dismiss'); if(!b)return;
  if(localStorage.getItem('ieslens.welcome')==='closed')b.checked=true;
  b.addEventListener('change',function(){
    if(b.checked){try{localStorage.setItem('ieslens.welcome','closed')}catch(e){}}
  });
}catch(e){}})();</script>

Two things to set before pasting

  • Replace TUTORIALS_URL_HERE with the tutorials page once it exists.
  • To centre it as a true modal instead of a corner card, change right/bottom to top:50%;left:50%;transform:translate(-50%,-50%).

2 · Search box

Typing a question and pressing Search opens IES Lens in a new tab with that query already run.

Preview

Opens lensy.ies.org/?q=… in a new tab.

HTML to paste

<!-- IES Lens — IES Standards Assistant. Opens lensy.ies.org in a new tab. -->
<form action="https://lensy.ies.org/" method="get" target="_blank" rel="noopener"
      style="display:flex;gap:8px;align-items:center;max-width:520px;margin:0 auto;font-family:inherit;">
  <input type="text" name="q" placeholder="Type a topic or ask a question"
         aria-label="Search the IES Lighting Library with IES Lens"
         style="flex:1 1 auto;min-width:0;padding:10px 14px;border:1px solid #D1D5DB;border-radius:10px;font-size:14px;color:#2C2C2C;background:#fff;">
  <button type="submit"
          style="flex:none;display:inline-flex;align-items:center;gap:6px;padding:10px 18px;border:0;border-radius:10px;background:#FFAA00;color:#30363D;font-size:14px;font-weight:700;cursor:pointer;">
    <svg width="14" height="14" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2.5" aria-hidden="true">
      <path stroke-linecap="round" stroke-linejoin="round" d="M21 21l-6-6m2-5a7 7 0 11-14 0 7 7 0 0114 0z"/>
    </svg>
    Search
  </button>
</form>

Notes

The panel works without JavaScript. Closing it is a hidden checkbox and a <label>, not a click handler, so it survives a header field that strips <script>. It does need the <style> block: the close behaviour is a sibling selector, which cannot be written as an inline style= attribute. If Vitrium strips <style> too, the fallback is the search box above — it is inline-styled throughout and needs neither.

Dismissal only sticks with the optional script. Nothing but JavaScript can remember a choice between page loads, so without it the panel returns on each visit. That is the honest trade, and it is why the script is separate and deletable rather than load-bearing.

No iframe. IES Lens sends frame-ancestors 'none', so it cannot be framed — embedding the search UI itself inside the portal is not possible, and would in any case put a second session boundary between the reader and their Library.

Sign-in is preserved. The query travels in the URL, and IES Lens's sign-in gate carries the whole path and query through the round trip — so a reader who is not yet signed in lands on their results, not on an empty search box.

Staging. To point either snippet at lensy-staging.ies.org, change the host in the action/href; nothing else depends on it.
