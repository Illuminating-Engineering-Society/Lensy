Maintenance

Flush the search cache

Bumps the corpus data version so every cached search response is invalidated. Use after out-of-band data changes (direct D1 writes, sync-metadata.js) that bypass the ingest endpoints. Cheap — one KV write; the next search of each query is simply uncached.

Scan for orphan vectors

Probes Vectorize for standard_id values with no row in D1. Read-only — it never deletes. Heuristic: re-run for higher confidence. LS-1 definition vectors are excluded by design (they have no standards row and never will). Deleting anything it finds is deliberately script-driven, not a dashboard button.

Data exports

Staff-only CSV exports. The two logs are anonymous by design; the reset queue is personal and stays behind this gate.

  • search-log.csv — every query, result count, low-confidence flag
  • search-events.csv — which cards readers opened, from what position
  • device-resets.csv — the Vitrium reset-request queue

Runbook pointers

  • • New or replacement PDFs: Standards & Indexing (upload → index → disposition).
  • • Access grants and invitations: Invited users.
  • • Vitrium metadata (titles, covers, buy links): npm run sync-metadata, then flush the cache here.
  • • Device resets are actioned in the Vitrium admin app (Users → “Clear Use”), then marked Done in the queue tab.
